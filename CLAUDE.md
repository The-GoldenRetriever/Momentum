# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

MOMENTUM is a pixel-art speed platformer written in plain browser JavaScript (ES modules, Canvas 2D, WebAudio). There's no build step, no package.json and no dependencies.

## Running

ES modules don't load over `file://`, so serve the repo root:

```sh
python3 -m http.server 8000      # then open http://localhost:8000/
```

The game opens on a title screen, then the level select, where a level opens only once the one before it is beaten, and some levels also ask for medals (`needs` in `levels/index.js`, checked by `src/save.js`). `?level=<n>` (1-based) skips the menus (and the locks) and starts that level, and `?at=<tileX>&ay=<tileY>` drops the player straight into a section of it (both handled in `Game`'s constructor; `main.js` turns the menus off when either is present).

## Tests and headless tools

This machine has no node, so use the system JavaScriptCore shell. The harness scripts are DOM-free and use jsc's `print` and `arguments`, not `console.log` or `process.argv`.

```sh
JSC=/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc
$JSC --module-file=tools/sim.js       # scripted physics checks; ends with "ALL PASS" or "N FAILURE(S)"
$JSC --module-file=tools/fuzz.js      # 90 seeded random-input runs per level; each must report "no embedded frames"
$JSC -m tools/invariants.js           # random input all over every level, asserting no glitch states; ends "no invariant broken"
$JSC -m tools/dump-level.js -- 0 60 3 # ASCII dump of tile columns 0..60 of level 3 (args go after --; level defaults to 1)
$JSC -m tools/dbg.js -- 656           # trace a run to the right from pixel x=656
$JSC -m tools/dbg2.js -- mantle       # canned test-area traces: mantle, mantle2, slide, slide2
$JSC -m tools/route.js -- 7 4 10      # run the course bot on level 7 from tile (4,10): every jump, and the time to the goal
$JSC -m tools/route.js -- 7 4 10 1    # ... with the bar held to one (a plain sprint); `- expert` instead dashes every straight
$JSC -m tools/windows.js -- 8         # every jump on level 8's route pressed earlier and later: its timing window in ms
```

- `tools/sim.js` has no test filter. Each check is a numbered `{ ... }` block that calls `check(name, ok, detail)`. To run one alone, comment out the others or copy the block into a scratch module (importing `sim.js` runs every check). The shared pieces live in `tools/harness.js`, which runs nothing on import: `makeSim({x, y}, customLevel?, { warp })` builds a level + player at a tile position (auto-burst off; `warp` runs the game's slow motion, otherwise every step is a full step of world time), and `run(steps, heldKeys | (i) => keys, onStep)` advances it at the fixed 1/120 step, ticking `updateMechanics` too. `flatOut(build, from, phaseT, route)` is the course bot (see check 32), and `tools/routes.js` holds each course's route. The bot runs the game's `Camera` alongside and reports blind falls: a landing not on screen when the jump was committed to (takeoff, or the last wall kick, dash or spring) or lost from view on the way down. Check 32 fails a course with any, judged on the run from the start (a respawn is a second look).
- Pixel checks use headless Chrome against the local server:
  ```sh
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
    --window-size=960,540 --virtual-time-budget=3000 --screenshot=out.png \
    "http://localhost:8000/tools/shot.html?at=150&ay=26&keys=right&steps=240"
  ```
  `tools/shot.html` is a deterministic frame grabber. Its params include `level`, `keys`, `steps`, `vx`, `flow`, `flip`, `duck`, `auto=vault|burst` (auto-burst is off in a grab unless `auto=burst`), `screen=title|select|pause|results` (with `sel=<row>`), `best=<id>:<seconds>,...` (stand-in saved times, for unlocks and medal gates), `next=<steps>` (finish, pick "next level", play that many steps of the cutscene) and `menu=open|capture` (the binding screen). The page title becomes `ready` when the frame is drawn (or `error: ...`). A tiny blank PNG with the title still `frame grab` means the modules hadn't loaded within the virtual-time budget. That's flaky, not a hang, so just retry. `tools/sheet.html?s=<zoom>&only=<anim,...>` renders the sprite sheet.

## Architecture

**Loop (`src/main.js`).** Physics runs on a fixed 1/120 s step with an accumulator, and rendering happens once per animation frame. The player's `warp` (1, `P.WIND_SCALE` through a burst's wind-up, `P.BURST_SCALE` in the burst) sets a global time scale that `main.js` eases toward, and the simulated step shrinks with it. So `Game.update(dt, input, realDt)` and `Player.update(dt, input, realDt)` take two clocks: `dt` is world time and `realDt` is wall-clock time. Almost everything uses `dt`. The burst wind-up and the binding menu use `realDt`.

**Input contract.** Gameplay never reads keys directly. It reads named actions through `held(a)`, `hit(a)` (press edge), `let_go(a)` (release edge), `moveX` and `moveY`. `src/input.js` maps keyboard and gamepad onto actions and stores rebinds in `localStorage` (`momentum.binds`). `keys` and `confirm` are fixed (not rebindable) so no binding can lock you out of the menus. There is no burst action: `autoburst` (V) switches automatic bursting off and on. An edge is consumed by exactly one physics step, and it waits for that step: `main.js` must not clear edges in a frame that ran no step (at 120Hz physics that is many frames on a fast display, and every frame of a burst's slow motion). Menus treat `up` as navigation even though ArrowUp/W are also `jump`. `tools/harness.js`, `tools/shot.html` and the `dbg` scripts each define a small `Keys` stub with the same interface. If you add an action or change the interface, update the stubs too.

**Module roles.**
- `game.js` (`Game`) owns the level, player, camera, renderer, particles, the menus and the binding screen. `load(n)` builds level `n` from `levels/index.js`, with a fresh player, camera and renderer; `start(n)` is the menu's way in. It handles checkpoints, signs, the goal and results, the run timer, respawn and restart, auto-pause on blur, and recording best times through `save.js`.
- `cutscene.js` draws what plays when you pick "next level": a letterboxed walk-off (`Game.nextLevel` feeds the player a held-right input capped at walking speed), a fade, then a black loading screen (the level's number and name, and the character's run cycle as a small white silhouette in the bottom-left); the next level is built behind it. Starting a level from the menu goes through the same card. The walk carries on through the level's invisible end wall and off screen (the camera stops at the edge), and the fade starts once the player is past it. Each level keeps a run-out of about twenty tiles past its goal, so that takes two or three seconds.
- `save.js` keeps a best time per level (`localStorage` key `momentum.best.<level id>`, which is what unlocks the next, along with any medals the next one `needs`: `unlocked`, `lockReason`) and the last level started (`momentum.last`). It is browser-only, so headless modules must never import it. `SAVE_VERSION` wipes old times once, on the first load after it changes (bindings are kept).
- `menus.js` (`Menus`) draws and drives the title, level select (with one-pixel-per-tile map thumbnails, and locked levels), pause menu and results panel. The title and level select show the loaded level as scenery (`renderer.hideActors`, a panning camera); pause and level-select-from-pause freeze the run; under the results panel the player coasts on an idle input.
- `player.js` holds all movement feel. Momentum is the core: the flow bar's overfill past one bar is a top gear (`RUN_OVER`), jumps lift more the faster you run (`JUMP_SPEED_LIFT`), friction and flow drain punish slowing down, and coming down is always free: no fall, drop or landing costs anything. A slope is the one place to outrun your legs: C on a downhill (`#slopeRollStep`) tucks you into a roll that adds `ROLL_DOWNHILL` with no drag or braking, up to `ROLL_MAX`, and you keep the speed off the bottom. Prompts show for ledges up and for downhills, never for ledges down. Water (`T.WATER`) holds you up only while `#skimming()` (at least `WATER_SKIM` and at least one bar, `WATER_FLOW`, burst or not; not sliding or crouching; and not `#plunging()`, a fall of more than `WATER_HIGH` from the top of the arc or the end of the last dash): the player sets `Level.skim` every step and every floor query reads it. Through the surface you wade (`#sink`/`#sinkStep`, `sinking` true, `dead` still false): you keep running or sliding while sinking at `SINK_SPEED`, C at a bank pulls you out while no deeper than `PULL_DEPTH` (a vault with `pull` set), and at `DROWN_DEPTH` you struggle for `STRUGGLE_TIME`, then `kill('water')`. The renderer draws a wading player half-submerged. Ice is a skin on SOLID rock (`Level.icy`, set by `ice()` or `freeze()`; queried by `iceUnder`, never by collision): `ICE_FRICTION`, `ICE_GRIP` and `ICE_TURN` scale the ground handling, and letting go glides (`gliding`, which holds the bar). A dash only comes back on the ground or from a crystal or spring, never from a wall, and hands off at `DASH_END` or the speed you went in with, whichever is higher. Boost pads also charge the bar to at least one. There is no burst button: sprint the bar to `BURST_ARM` (near the top) with `autoBurst` on and a wind-up starts (`burstWind`, `BURST_WIND` real seconds of slow motion while the last of the bar crawls in), then the burst fires by itself; it burns the bar at `BURST_DRAIN` until it runs dry. V (`autoburst`) toggles `autoBurst`, which outlives respawns; `Game` hands it to each new level's player and saves it (`momentum.autoburst`). `startBurst()` is public so sim checks can start one without the wind-up. A level's `dashFrom`/`burstFrom` (px) withhold the dash and the burst west of them (the tutorial hands them over at their sections). It covers run, flow meter, jump, wall jump, dash, slide, vault and roll on ledge cues, burst, and skid. Tuning constants live in the exported `P` table. The header comment states the design rules (speed is earned slowly and lost reluctantly, and nothing that costs speed happens unless the player asks). Collision is integrated per axis in `#moveX` and `#moveY`, with step-ups, slope lift, one-way platforms and corner correction.
- `level.js` (`Level`) is pure data and math: the tile grid (`T` enum, with `SPAN` for partial-height solids such as `LOWCEIL`), authoring helpers (`rect`, `platform`, `spikes`, `stairs`, `ramp`, `crystal`, `spring`, `checkpoint`, `sign`, `crumble`, `phase`, `boost`) and every collision query (`boxHitsWall`, `floorUnder`, `ceilingAbove`, `slopeUnder`, `boxHitsSpikes`, `boxInWater`, ...). `slopeUnder` allows for the half-width gap a box rides above a slope going downhill; without it, downhill pushes almost never applied. `water(...)` lays a body of water and `stillness(speed, lead, reach)` sets the Stillness on a level. Levels have a rock wall on the left only: the right edge of the grid is an invisible wall in `boxHitsWall`, `get` carries the last column on past it (so ground continues off screen and the bake draws no cliff face), and `exitOpen` lets the walk-off through.
- `mechanics.js` runs the level furniture that acts on the player: crumbling blocks (`T.CRUMBLE`), the two alternating sets of phase blocks (`T.PHASE`), boost pads, springs and crystals. Because it is headless-safe, `makeSim`, the fuzzer and the game all run the same rules. A block that is "away" is just set to `T.EMPTY`, so collision queries need no special cases. Blocks never reappear inside the player. A boost pad built with `{ sync }` restarts the phase clock when stepped on, which makes a phase crossing beyond it deterministic (the spire's phase pit relies on this). `resetMechanics(L, fromX)` restores crumbles on respawn and puts the Stillness `lead` tiles behind where you come back in. The Stillness (`L.chase`) waits until you move, gathers from half its pace to all of it over `STILL_GATHER` seconds, is never more than `reach` tiles behind, kills on contact (`kill('still')`) and stops once the goal is hit. Tuning lives in its `M` table.
- `levels/index.js` lists the levels in order (`id` keys the saved best time, so don't change it). `levels/tutorial.js` is level 1, "first steps": every move one at a time, each gate passable only with its move (vault steps with spiked roofs, a slide tunnel with gaps, a sealed shaft, a roll gap, a dash cliff, a burst chasm, and a sea that wants auto-burst off); the dash and burst are withheld until their sections. Its route runs with `warp` and `autoBurst` on, and sim.js check 40 proves each move is needed. `levels/test-area.js` is level 2, "proving ground" (id `testarea`), a 330×42-tile playground split into lettered sections, and still the sim checks' default playground. Each section isolates one mechanic and can be entered at full speed from the one before it. `levels/spire.js` (level 3), `levels/undercroft.js` (4, a cave) and `levels/skyline.js` (5, floating islands over a void) are courses built to be run flat out, getting harder in that order. `levels/tidewater.js` (6, the glass sea: water you run on, reefs, arches to slide on rock), `levels/stillness.js` (7, the Stillness chases you the whole way, with ice in its last section), `levels/overpass.js` (8, parkour on girders over a flood, with a stretch run on the water), `levels/updraft.js` (9, springs that keep your speed: top-gear launches, fanged trap springs to hop, a dash off a spring, a crystal chain), `levels/furnace.js` (10, under a low roof that keeps changing, with the Stillness behind you) and `levels/glacier.js` (11, all ice, a meltwater lake, and icefalls too high for the water to hold you unless you dash just before it; stillness's last section is its ice intro) are the momentum courses: no boost pads, a long run-up after every flag (a respawn means an empty bar), and gaps placed where a top-gear jump lands, past what a sprint clears. They mark themselves (`L.marks`: flags, fang hops, run-up ends, zones, tunnels), and `routes.js` builds their routes from that, so retuning a gap never strands the route. `sim.js` check 32 proves each course with a scripted bot from the start and every flag. Where a level demands more than running and jumping (hops under fangs, dashes across gaps, `roll`, `vault` to stop the bot jumping a ledge's gap, `autoburst` for V), the route lists it as a zone, and the check also proves each zone is needed. A route can also claim `topGear` (from a flag, held to a plain sprint, the bot fails before the next flag). Chases are live in the bot's runs too, so a course with the Stillness is proved with it on. The routes live in `tools/routes.js`; if you move geometry in these levels, move the route with it (`tools/route.js` prints where the jumps land). Undercroft and Skyline are built from "stations" (a flag with a boost pad right after it) followed by platforms too small to stop on, placed where a full-speed jump from the pad lands; tune them by probing where the bot's jumps come down. A level's `needs` (`{ silver: 3 }`) gates it behind medals earned anywhere, a better medal counting as the lesser ones (`medalTally`, `medalsShort`; check 41 keeps every gate payable from the levels before it). Each level's `par` in `levels/index.js` is the bot's flat-out time from the start, and the medals (`medalTimes`) are fractions of it (a level's own `medals` overrides them: the momentum courses use tighter ones, since the bot's run there is near the best line). Gold has to beat the expert bot (`expert`: dashes chained down every straight, never into a zone), which check 32 enforces wherever the expert finishes; aim for gold at about 0.95 of the expert's time (bursts do not beat it: they spend the bar the top-gear gaps need), silver near the expert, bronze just under the bot; re-measure par with `tools/route.js` if a level or the physics changes. A level sets `L.theme` (`night`, `cave`, `dusk`, `tide`, `frost`, `dawn`, `aurora`, `ember`, `glacier`) to pick its look; a theme's `water` colours, if any, tint its water. No blind falls is a design rule: the camera shows about twenty tiles ahead at top gear and about seven rows below, so keep drops within that. Sim checks address sections by tile coordinates, so moving geometry can break `tools/sim.js`.
- `camera.js` follows with a look-ahead that grows with speed, leads by its own easing lag (an eased follow trails a moving target by speed / ease, which at top gear hid the landing of every full-speed jump), looks down hard when falling and barely up when rising, and frames the player a little above centre.
- `render.js` (`Renderer`) bakes the whole tile map and the sky into offscreen canvases **once, in its constructor**. Changing tiles at runtime won't show up unless the bake is redone. The bake only sees permanent rock (its `rock()` helper). Colours for sky, ridges, rock and growth come from the level's entry in `THEMES`, read only while baking. Crumble and phase blocks and boost pads are drawn live in `#furniture`. The view is fixed at 480×270 (`VIEW_W`/`VIEW_H`). Burst zoom is a nearest-neighbour blow-up of a finished frame, not a transform, so edges stay crisp.
- `art.js` stores sprites as string grids (one character per pixel, indexed into `PAL`, 16×18 frames, foot-anchored). `buildArt()` turns them into canvases at startup, and `FRAMES`/`FRAME_COUNT` define the animations. `font.js` is a 3×5 bitmap font. `hud.js`, `binds.js`, `camera.js`, `particles.js` and `audio.js` (a pure oscillator synth) are self-contained.

**Headless-safe modules.** `level.js`, `player.js`, `particles.js`, `mechanics.js` and `levels/*` are loaded by jsc with no DOM present. Keep DOM, `window` and `localStorage` access out of them and out of anything they import at module load time (`art.js` and `audio.js` are imported by `player.js`; their DOM work happens only in `buildArt()` and lazily in `Sfx`).

## Conventions

Comments explain *why* in full sentences (feel decisions, edge cases, past bugs) rather than restating the code. Match that density when editing. Before claiming a physics change works, run both `sim.js` and `fuzz.js`. For a visual change, take a screenshot and look at it.
